## What this repo is

Bài 3 (dữ liệu ảnh) of the CO3117 Machine Learning course assignment
(`mlAssignments_v1.1.pdf`, section 4.3). The deliverable is a **Google Colab
notebook** that builds an image-classification pipeline end-to-end on the
INRIA Person dataset:

```
EDA  ->  Build dataset  ->  Deep feature extraction  ->  Classifier comparison  ->  Best-model analysis  ->  (Bonus) End-to-end VGG16
```

The pipeline is configurable via a single `CONFIG` dict in the notebook
(image size, feature extractor, classifier, epochs, etc.).

## Repository layout

```
notebooks/ex3_imageData.ipynb   <-- the front-end Colab notebook
modules/
    ml_utils.py                 # dataset discovery, EDA, classifier comparison, feature I/O
    dl_utils.py                 # pretrained feature extraction + transfer-learning helpers
features/                       # generated .npy files (one X + one y per feature extractor)
reports/                        # report.pdf (export of report.md)
report.md                       # source for the PDF report
mlAssignments_v1.1.pdf          # assignment spec
README.md                       # group / course metadata for graders
requirement.txt                 # local-run pip requirements
```

`features/` is regenerated by running the notebook. The `bai3.npy` placeholder
in there is a stub.

## How to run

### Google Colab (primary path)

1. Click the *Open in Colab* badge at the top of `notebooks/ex3_imageData.ipynb`.
2. `Runtime -> Run all`.

The first code cell clones the repo into `/content/Hybrid-Image-Classification`,
adds `modules/` to `sys.path`, and installs missing pip packages (`kagglehub`,
`scikit-learn`, `Pillow`, `seaborn`). No Drive mount, no manual upload.

The dataset is fetched via `kagglehub.dataset_download("jcoral02/inriaperson")`.
On Colab this works without credentials for public datasets in most cases;
if a Kaggle 401 fires, the cell prints instructions to add a `KAGGLE_USERNAME`
/ `KAGGLE_KEY` Secret.

### Local (Python >= 3.10)

```bash
pip install -r requirement.txt
jupyter lab notebooks/ex3_imageData.ipynb
```

Anything that imports `tensorflow.keras.applications` (feature extraction,
end-to-end VGG16) needs TensorFlow installed.

## Module conventions

- `ml_utils.py` is **TensorFlow-free** -- safe to import for classical-only
  flows. Do not add a top-level TF import.
- `dl_utils.py` imports TF lazily inside each function so that callers who
  only use `ml_utils` do not pay the TF startup cost.
- Feature files are persisted as `features/<model>_X.npy` and
  `<model>_y.npy` (see `ml_utils.save_features` / `load_features`). New
  feature extractors should follow this naming convention so the notebook's
  comparison cell picks them up automatically.

## Conventions for changes

- **Do not** rename the `CONFIG` keys without updating every cell that reads
  them -- the notebook treats `CONFIG` as the single source of truth.
- The notebook must remain runnable top-to-bottom under `Run all`. Any new
  cell that takes more than a couple of minutes needs a sensible default
  (small epoch count, batch cap, etc.) so total wall-clock stays reasonable
  on free-tier Colab CPU.
- The Colab badge URL pins `branch=main`. Push new code to `main` before
  asking graders to open the notebook.
